# supabase/

Database, storage and auth for `ap-emp-ai`.

## Layout

- `config.toml` — local stack config (generated by `supabase init`, `project_id = ap-emp-ai`).
  Postgres 17 on port 54322, API on 54321, Studio on 54323.
- `migrations/` — applied in filename order. `20260803000001_initial_schema.sql` is
  migration 001: the schema in `PLAN.md` Part 3 plus the retrieval indexes.
- `tests/` — SQL smoke tests asserting the schema behaves as intended.

Migration filenames must follow the CLI's `YYYYMMDDHHMMSS_name.sql` convention —
create them with `supabase migration new <name>` rather than by hand.

## Running it

```bash
pnpm db:start     # boots the local stack (needs Docker)
pnpm db:reset     # drops, recreates and re-applies every migration
pnpm db:test      # runs supabase/tests/001_schema_smoke.sql against the local db
pnpm db:stop
```

## What migration 001 sets up

| Table | Notes |
|---|---|
| `documents` | One row per GO/Memo/Circular. `sha256` unique — identity is the PDF bytes, since the same GO arrives from goir, the e-Gazette, Telegram and WhatsApp. `status` defaults to `pending`. |
| `chunks` | `embedding vector(1024)` with an HNSW index (cosine), plus a **generated** `tsv` column with a GIN index. |
| `rates` | Every DA %, HRA slab, master scale and IT slab, with `source_go` (CLAUDE.md rule 1). |
| `chat_logs` | Question, answer, `cited_docs`, 👍/👎 feedback. |
| `ingest_queue` | Everything inbound, before it becomes a document. |
| `users` | Employee profile + DPDP consent log. Phase 6 links `id` to `auth.users(id)`. |

Two decisions worth knowing about:

- **`tsv` is a generated column**, not one the application writes, so the keyword
  half of hybrid search cannot drift out of sync with the text. It uses the
  `simple` text-search config rather than `english`: the corpus is bilingual and
  Postgres has no Telugu stemmer, so tokenising without stemming beats stemming
  one language and mangling the other.
- **RLS is on for all six tables.** Without it, anything in the `public` schema is
  readable by anyone holding the anon key. Anon/authenticated can read approved
  documents, their chunks, and rates — nothing else. `chat_logs`, `ingest_queue`
  and `users` are service-role only until Phase 6 adds auth and per-user
  ownership. The ingestion pipeline and admin queue use the service role, which
  bypasses RLS.

Service keys live in `.env` only and are never committed (CLAUDE.md hard rule 7).
